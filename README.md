# 프론트엔드 세미나 4주차 과제

## 목표

비동기 처리와 `Promise`를 활용하여 레시피 목록 및 상세 페이지를 구현합니다. 제공된 Mock Data를 서비스 계층을 통해 비동기로 조회하고, 데이터를 불러오는 동안 로딩 상태를 표시합니다.

이번 주 과제는 **조별 과제 환경 설정**, **천개의 레시피 만들기**, **블로그 글 작성**으로 구성됩니다.

## 과제 1. 조별 환경 세팅 인증

이번 주에는 조별로 과제를 진행합니다. 팀원들과 GitHub 레포지토리를 설정하고 Pull Request(PR) 리뷰 과정을 실습합니다.

### (1) 레포지토리 설정

- 팀장은 [템플릿 레포지토리](https://github.com/WaffleStudio24-5/frontend-seminar-week4-template)를 이용해 새 레포지토리를 생성합니다.
- 레포지토리 소유자(owner)는 팀장 본인으로 설정합니다.
- 팀원들은 GitHub 아이디를 팀장에게 전달하고, 팀장은 팀원들을 `outside collaborator`로 초대합니다.
- 레포지토리의 PR 및 Ruleset 설정은 [4주차 세미나 자료](https://github.com/WaffleStudio24-5/frontend-seminar-week4-template)와 수업 안내를 참고하여 진행합니다.

### (2) 코드 리뷰 실습

- 이름을 가나다순으로 정렬했을 때 마지막인 팀원이 `README.md`를 생성하여 조원들의 이름을 작성하고 PR을 올립니다.
- 다른 팀원들은 PR을 리뷰하고 `Approve`한 뒤 머지합니다.
- **11월 16일 오후 6시 전까지** PR 리뷰 승인 및 머지가 완료된 화면을 캡처하여 **`f-잡담`** 채널에 업로드합니다.

## 과제 2. 천개의 레시피 만들기

제공된 Mock Data를 이용해 레시피 목록과 상세 페이지를 구현합니다. **실제 서버 통신은 구현하지 않습니다.**

- [동작 참고 사이트](https://fe-seminar-week4.vercel.app)

디자인을 완전히 동일하게 구현할 필요는 없지만, 아래 기능은 모두 구현해야 합니다.

### (1) 메인 페이지

- 레시피를 카드 형태로 표시합니다.
- 태그를 선택하여 레시피를 필터링할 수 있어야 합니다.
  - 여러 태그를 동시에 선택할 수 있어야 합니다.
  - `전체`를 선택하면 다른 태그 선택이 해제됩니다.
- 레시피 목록에 페이지네이션을 구현합니다.
  - **한 페이지에 6개**의 레시피를 표시합니다.
- 레시피 카드를 통해 해당 레시피의 상세 페이지로 이동할 수 있어야 합니다.

### (2) 상세 페이지

- 선택한 레시피의 다음 정보를 표시합니다.
  - 요리명
  - 조리시간
  - 재료
  - 레시피
  - 요리 정보
- 현재 레시피와 **태그가 하나 이상 겹치는 다른 레시피**를 추천 목록에 표시합니다.
  - 현재 보고 있는 레시피는 추천 목록에서 제외합니다.
  - 추천 목록은 **가로 스크롤 및 무한 캐러셀** 형태로 구현합니다.
  - 캐러셀에 마우스를 올리면(`hover`) 애니메이션이 일시 정지되어야 합니다.

### (3) 데이터 사용 규칙

- 레포지토리의 `src/data` 폴더에 제공된 TypeScript 파일을 사용합니다.
- 제공된 Mock Data의 **필드명과 데이터 구조를 수정하지 않습니다.**
- 화면에서 필요한 정보는 제공된 필드를 그대로 사용합니다.
- 페이지나 컴포넌트에서 Mock Data를 직접 `import`하지 않습니다.
- 데이터 타입은 `src/types/recipe.ts`를 참고할 수 있습니다.

### (4) recipeService 구현

화면 코드에서 Mock Data에 직접 접근하지 않도록 `recipeService` 계층을 구현합니다.

```text
Page / Component → recipeService → Mock Data
```

다음 조건을 만족해야 합니다.

- Mock Data는 `recipeService` 내부에서만 `import`합니다.
- 모든 데이터 조회 함수는 `Promise`를 반환해야 합니다.
- `setTimeout`을 이용해 **1,000ms 이상**의 응답 지연을 구현합니다.
- 데이터를 불러오는 동안 해당 UI에 **로딩 상태**를 표시합니다.
- `src/services` 폴더의 예시를 참고하여 필요한 데이터 조회 함수를 직접 구현합니다.

예시:

```ts
// src/services/recipeService.ts
import { recipes } from "../data/recipes.js";

export const getRecipes = () => {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve(recipes);
    }, 1000);
  });
};
```

## 과제 3. 블로그 글 작성

이번 세미나에서 배운 내용이나 과제 수행 경험을 바탕으로 자신의 관점이나 의견이 담긴 블로그 글을 하나 작성합니다.

- 주제 예시: 에러 해결 과정, 배운 내용 정리, 과제 후기 등
- 배운 내용을 그대로 복사하거나 단순한 일기 형식으로 작성하는 것은 지양합니다.
- 티스토리, 네이버 블로그, Velog 등 플랫폼 제한은 없습니다.
- **11월 16일 오후 6시까지** 작성한 글의 링크를 **`f-잡담`** 채널에 공유합니다.
